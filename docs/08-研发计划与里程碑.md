### M6 之后：发布证据存证

交付：`internal/platform/artifact`（gRPC 客户端 + client_credentials 令牌）、
`SealEvidence` 活动（`CreateContent → CreateResource(INLINE_TEXT) → SealRevision → 回读校验`）、
`cmd/evidence-check` 自检工具、`scripts/test-evidence.sh` 验收脚本；
artifact 侧新增 `devmaster` registry profile（`devmaster.release-notes` /
`devmaster.test-report`，仅 `INLINE_TEXT`、角色 `evidence`、上限 64 KiB）。

设计取舍：
- **证据文本不含时间戳**：Temporal 重放时文本一变，载荷指纹就变，同一版本会
  封出第二份内容。时间看 artifact 的 `revision.created_at`。
- **幂等键 = 载荷指纹**（类型 + 标题 + 元数据 + 角色 + 字节的 SHA-256 前 20 字节），
  重试命中 artifact 幂等记录并回放同一修订。
- **已密封视为成功**：重试时修订可能早就是 `SEALED`，`SealRevision` 会以
  `FailedPrecondition` 拒绝；确认密封态成立后放行，否则工作流重试永远过不去。
- **存证在发布之前**：evidence_ref 是发布记录的一部分，不产出「发布了但没证据」的记录。

证据（本地真栈：Keycloak realm `artifact` + content-api `:50071`）：
- `make test-evidence` 通过：首封新建、重放命中同一修订（`replayed=true`）、
  载荷变化落成新修订；
- 库内核对：`content_revisions.state=SEALED`、`manifest_hash` 非空、
  `sha256(content_resources.inline_text)` 与回执 `payload_sha256` 逐字节一致。

欠账：回放路径拿不到 `manifest_hash`（proto 的 `ContentRevision` 未暴露该字段，
`GetContent` 只回状态），不影响 `evidence_ref` 语义。
