# 04 领域模型与数据设计

> 上游：[02 范围与边界](02-需求范围与系统边界.md)、[03 架构](03-总体架构与技术落地.md)。
> 本文是 schema 与状态机的唯一依据；改模型先改本文，再改 ent schema 与迁移。

## 1. 聚合与模块边界

```text
product    ── Product / Component / Member / FieldRegistry
workitem   ── WorkItem / Link / Comment / Attachment / Commit / Event
sprint     ── Board / Sprint / ScopeEvent / DailySnapshot
version    ── Version / ReleaseRecord
worklog    ── WorkLog
```

聚合根与一致性边界：

| 聚合根 | 内部强一致 | 跨聚合通过 |
|---|---|---|
| `Product` | 组件树、成员、字段注册表 | 只被引用 |
| `WorkItem` | 状态、字段、链接、评论、提交关联、事件 | `sprint_id` / `version_id` 是外键，但迁移由 sprint/version 侧发起 |
| `Sprint` | 状态、范围事件、快照 | 关闭时批量改 `work_items.sprint_id`（同事务） |
| `Version` | 状态、scope（`work_items.version_id`）、发布记录 | 发布时锁 version 行 |
| `WorkLog` | 单条记录不可变 | 反向记录引用原记录 |

**没有 `Project` 聚合**（01 ADR-0001）。`project_code` 是工作项上的字符串。

## 2. 表设计

> 所有表带 `organization_id`（除全局字典），RLS 按此列隔离。时间统一 `timestamptz`（UTC）。
> 主键统一 `uuid`（`gen_random_uuid()`），事件表用 `bigserial`（有序、窄）。


## 3. 状态机

### 3.1 迁移表

| 类型 | from | to | 守卫 |
|---|---|---|---|
| `EPIC` | `OPEN` | `IN_PROGRESS` | — |
| `EPIC` | `IN_PROGRESS` | `DONE` | — |
| `STORY`/`TASK` | `BACKLOG` | `TODO` | 必须已进 sprint（同事务完成"入 sprint + 提状态"） |
| `STORY`/`TASK` | `TODO` | `IN_PROGRESS` | 必须有经办人 |
| `STORY`/`TASK` | `IN_PROGRESS` | `IN_REVIEW` | `require_pr=true` 时：至少一个 `MERGED` PR |
| `STORY`/`TASK` | `IN_REVIEW` | `DONE` | `require_pr=true` 时：同上 |
| `STORY`/`TASK` | `IN_REVIEW` | `IN_PROGRESS` | 评审退回 |
| `BUG` | `OPEN` | `IN_PROGRESS` | 必须有经办人 + 组件 |
| `BUG` | `IN_PROGRESS` | `RESOLVED` | 必须带 resolution；`require_fix_version=true` 时必须带 `version_id` |
| `BUG` | `RESOLVED` | `VERIFIED` | 只能是报告人或 `DEV_LEAD` |
| `BUG` | `VERIFIED` | `CLOSED` | 必须带 resolution |
| `BUG` | `RESOLVED`/`VERIFIED` | `REOPENED` | `reopened_count += 1`，清空 `resolved_at` |
| `BUG` | `REOPENED` | `IN_PROGRESS` | — |
| `BUG` | `OPEN` | `WONTFIX` | 必须带 resolution=`WONTFIX` + 评论 |
| 任意 | 任意非终态 | `CANCELLED` | 仅 `DEV_LEAD`，必须带原因 |

**终态**：`DONE` / `CLOSED` / `WONTFIX` / `CANCELLED`。终态不可回退（BUG 的 `REOPENED` 是
从 `RESOLVED`/`VERIFIED` 出发，不是从 `CLOSED`）。

### 3.2 状态与列

不同工作项类型的状态名不同，看板列按**状态类别**映射（列固定四列）：

| 状态 | 类型 | 看板列 | 计入燃尽剩余 |
|---|---|---|---|
| `BACKLOG` | STORY/TASK | 不进看板（`sprint_id` 必为 null） | ❌ |
| `TODO` | STORY/TASK | 待办 | ✅ |
| `OPEN` / `REOPENED` | BUG | 待办 | ✅ |
| `IN_PROGRESS` | 全部 | 进行中 | ✅ |
| `IN_REVIEW` | STORY/TASK | 评审中 | ✅ |
| `RESOLVED` | BUG | 评审中（待验证） | ✅ |
| `DONE` / `VERIFIED` | STORY/TASK / BUG | 完成 | ❌ |
| `CLOSED` / `WONTFIX` | BUG | 完成 | ❌ |
| `CANCELLED` | 全部 | 不进看板（从 scope 移除时写 `REMOVED`） | ❌ |

### 3.3 实现方式

- 迁移表是代码里的 `map[Type]map[Status][]Transition`，启动时校验完整性
  （每个状态至少一条出边，除非是终态）；
- `Transition()` 是唯一写入口：校验 → 守卫 → 写 `work_items`（CAS）→ 写事件 → 写 outbox；
- **静态检查**：`internal/workitem` 之外禁止出现 `SetStatus`；CI 用 `go vet` 自定义分析器或
  简单 grep 门禁（`status\s*=` 只允许出现在 `internal/workitem/domain`）。

## 4. 不变量

| # | 不变量 | 强制 |
|---|---|---|
| I1 | 一个 Board 同时最多一个 `ACTIVE` sprint | 部分唯一索引 `sprints_one_active` |
| I2 | 一个工作项同时只属于一个 sprint；跨 sprint 移动必须成对写 `REMOVED` + `ADDED` | `sprint_id` 单列 + 领域层成对写事件（集成测试断言事件成对） |
| I3 | 状态迁移必须走迁移表，且每次迁移写事件 + outbox（同事务） | 唯一入口 + 事务测试 |
| I4 | `RELEASED` 版本的 scope 冻结 | 触发器拒绝 `work_items.version_id` 变更（当版本已 `RELEASED`） |
| I5 | `work_logs` 不可 UPDATE/DELETE | 数据库只授 `INSERT`/`SELECT`；反向记录 |
| I6 | 工作项编号在组织内唯一且单调 | `product_counters` 行锁 + 唯一索引 |
| I7 | 同一版本同时只有一个进行中的发布尝试 | 部分唯一索引 `release_records_inflight` |
| I8 | 工时挂的工作项必须属于同一组织 | 复合外键 `(organization_id, work_item_id)` |
| I9 | `status='BACKLOG'` ⇒ `sprint_id IS NULL`；加入 sprint 时同事务提升为 `TODO` | 应用层 + 集成测试（不允许"在板上但仍是 backlog"） |

## 5. 编号与排序

### 5.1 工作项编号

```sql
BEGIN;
UPDATE product_counters SET next_seq = next_seq + 1
 WHERE product_id = $1 RETURNING next_seq;          -- 行锁，事务结束释放
INSERT INTO work_items (key, ...) VALUES ($product_key || '-' || $seq, ...);
COMMIT;
```

- 编号不回收（删除是软删/归档，`CANCELLED` 也占号）；
- 前缀取自 `products.key`，产品改名不改前缀（前缀是历史事实）。

### 5.2 LexoRank

- 字符集 `0123456789abcdefghijklmnopqrstuvwxyz`（36 进制，字典序即顺序）；
- `Between(a, b)`：找到首个不同字符，取两字符中点；若无空隙，在 `a` 后追加中点字符；
- 首位插入取 `a` 的前驱（用 `0` + 中点递归）；末位插入追加中点；
- **Rebalance**：当某列最大 rank 长度 > 24 时，后台重写该列（按当前顺序生成等距 rank），
  单次一个事务、按 board 加锁、写一条 `RANK_REBALANCED` 审计事件；
- 性质（单测）：`a < Between(a,b) < b`；幂等（同 a/b 多次调用结果一致）。

## 6. 事件：领域事件 vs 集成事件

| 领域事件（`work_item_events`） | 是否出站 | 说明 |
|---|---|---|
| `created` | ✅ | 新工作项 |
| `transitioned` | ✅ | 状态迁移（含 from/to/resolution） |
| `assigned` | ✅ | 指派变更 |
| `updated` | ❌ | 字段编辑，只进 `audit_field_changes` |
| `linked` / `unlinked` | ❌ | 内部关系 |
| `comment.added` | ❌ | 评论不外发（可能含敏感内容） |
| `attachment.added` | ❌ | 只存引用 |

| 领域事件（其他聚合） | 是否出站 |
|---|---|
| `sprint.started` / `sprint.closed` | ✅ |
| `sprint.scope_changed` | ❌（进快照与报表，不外发） |
| `version.released` | ✅ |
| `release.submitted` | ✅（自寻址：只给自身 consumer 起工作流，外部不承诺） |
| `release.approved/failed` | ❌（审批状态在 approver 侧可查） |
| `work.logged` / `work.reversed` | ✅ |

**出站事件的最小化原则**：只发"别的系统需要据此行动"的事实。评论、字段编辑、scope 变更
都不发——它们只服务于本系统的审计与报表。

## 7. 索引与查询

已在上文随表列出。补充三条设计说明：

1. **部分索引优先**：`WHERE sprint_id IS NOT NULL` 让看板索引只覆盖在板上的项（通常 < 5%），
   索引体积小一个数量级。
2. **`custom_fields` 用 `jsonb_path_ops`**：只支持 `@>` 包含查询，体积比默认 GIN 小，
   够用（自定义字段的查询都是等值）。
3. **`work_item_events` 先不分区**，但建表时就用 `partition by range (occurred_at)` + 一个
   默认分区；到 500 万行再按月建分区（`ATTACH PARTITION` 不锁表）。

## 8. 数据保留与归档

| 数据 | 保留 | 方式 |
|---|---|---|
| `work_items` / `versions` / `work_logs` | 永久 | 软删（`ARCHIVED` / `CANCELLED`） |
| `work_item_events` | 永久 | 月分区；超过 24 个月的分区可冷备后 detach |
| `audit_field_changes` | 180 天 | 每日清理 |
| `idempotency_keys` | 7 天 | 每日清理 |
| `outbox_events` | 30 天（已发送） | 每日清理 |
| `sprint_daily_snapshot` | 永久 | 体积极小 |
| 附件字节 | 由 artifact 决定 | devmaster 只存引用 |

## 9. 并发与锁

| 操作 | 锁 | 冲突处理 |
|---|---|---|
| 编辑工作项 | CAS（`version`） | `ABORTED` + 返回当前版本，前端提示"已被他人修改" |
| 拖拽（改状态 + 排序） | 单事务 + CAS | 同上 |
| 开始/关闭 sprint | `SELECT ... FOR UPDATE` on sprint | 串行化，第二次调用返回状态冲突 |
| 发布提交 | 锁 version 行 | 已有进行中的 ReleaseRecord 时返回 `FAILED_PRECONDITION` |
| 编号生成 | `product_counters` 行锁 | 串行，吞吐足够（单产品每秒 < 100 个新项） |
| 工时写入 | 无锁（append） | 天然无冲突 |

## 10. 测试策略

| 层 | 覆盖 | 门禁 |
|---|---|---|
| 状态机单测 | 所有 `(type, from, to)` 组合，合法与非法各一遍 | `go test ./internal/workitem/...` |
