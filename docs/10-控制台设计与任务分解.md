## 2. 设计原则

1. **无客户端 JS 优先**。表单用原生 `form` + 303 回跳，写操作走 BFF route handler 签名。
   只有看板拖拽这类必须交互的场景才引客户端组件。
2. **校验与状态机由后端给**。前端不复制状态机（`next_statuses` 由 API 返回），
   也不自己判断权限——守卫在领域层。
3. **写操作的 actor 一律取自会话**，客户端传不了。BFF 签名覆盖 body。
4. **每页三段式**：筛选条 → 列表/主内容 → 行内操作。操作失败用 `?error=` 回跳提示，
   不弹窗（无 JS 也能工作）。
5. **空态要说清楚下一步**。不是「暂无数据」，而是「还没有版本。用版本页新建一个」。

## 4. 页面设计

### 4.1 工作项详情 `/work-items/[key]`

**为什么先做**：列表只能看标题和状态，评论与历史是协作的核心；现在这些只能查库。

```text
面包屑：工作项 / HOSP-3
┌ 标题 + 类型 + 状态 pill + 优先级 ────────────┐
│ 经办人 · 报告人 · 版本 · 更新时间              │
│ 描述（Markdown 原文）                          │
└───────────────────────────────────────────────┘
┌ 流转（沿用列表页的行内表单）──────────────────┐
┌ 评论 ────────────────────────────────────────┐
│ 列表（时间倒序）+ 输入框 + 提交                │
└───────────────────────────────────────────────┘
┌ 关联 ────────────────────────────────────────┐
│ 出向/入向分组显示，+ 添加（选择目标 key + 类型）│
└───────────────────────────────────────────────┘
┌ 事件历史 ────────────────────────────────────┐
│ 时间 · 事件类型 · actor · 变化摘要（折叠 JSON）│
└───────────────────────────────────────────────┘
```

依赖 API：`GET /api/work-items/{key}`、`GET/POST /api/work-items/{id}/comments`、
`GET /api/work-items/{id}/events`、`GET/POST/DELETE /api/work-items/{id}/links`。

### 4.2 工时 `/worklogs`

**为什么第二**：链 B（工时 → PPM 成本）的入口，现在完全空白；M4 的后端一行都用不上。

```text
筛选：产品 · 成员 · 时间范围
┌ 汇总卡：总工时 / 人数 / 条目数 ────────────────┐
┌ 记工时表单：工作项（按 key 搜）+ 日期 + 分钟 + 备注 │
┌ 列表：日期 · 工作项 · 成员 · 分钟 · 备注 · 操作(冲正) │
└───────────────────────────────────────────────┘
```

冲正是负向追加，不是修改：输入冲正分钟数 + 理由，生成一条反向记录。
列表里正负分色显示（增红减绿不符合工时语义，用工时用蓝/灰）。

依赖 API：`GET /api/worklogs`、`POST /api/worklogs`、`POST /api/worklogs/{id}/reverse`、
`GET /api/worklogs/summary`。

### 4.3 冲刺 `/sprints`

```text
筛选：产品
┌ 列表：名称 · 状态 · 起止 · 承诺/新增/移除 · 操作 ┐
│ 操作：开始 / 结束 / 管理范围                     │
└───────────────────────────────────────────────┘
┌ 选中冲刺的详情：燃尽图（ASCII 折线）+ 范围事件   │
└───────────────────────────────────────────────┘
```

燃尽图不引图表库：用 SVG 折线，数据来自 `GetBurndown`。

依赖 API：`GET/POST /api/sprints`、`POST /api/sprints/{id}/start|close`、
`POST /api/sprints/{id}/items`（加/移）、`GET /api/sprints/{id}/burndown`。

### 4.4 版本与产品

- `/versions` 加「新建版本」表单（名称、里程碑、计划日期）与「挂工作项」（多选未挂项的工作项）。
- `/` 加「新建产品」表单（key、名称、描述）。

### 4.5 看板 `/board`

现在是只读列。目标：**拖动卡片改状态**。这是唯一需要客户端组件的页面——
用原生 HTML5 drag & drop + 一个 client component 包住列，落点时调 `POST /api/board/move`。

因为需要 JS，放在最后：先把无 JS 的路径补完，再考虑交互增强。

### 4.6 通用体验

- 导航分组 + 当前页高亮
- 统一空态文案（说下一步做什么）
- 列表分页（工作项 > 50 时）
- 时间统一 `zh-CN` 本地化 + 相对时间（「3 小时前」）

## 5. API 缺口清单

| 端点 | 方法 | 用途 |
|---|---|---|
| `/api/work-items/{key}` | GET | 详情（按 key 而非 id，便于人读 URL） |
| `/api/work-items/{id}/comments` | GET/POST | 评论 |
| `/api/work-items/{id}/events` | GET | 事件历史 |
| `/api/work-items/{id}/links` | GET/POST/DELETE | 关联 |
| `/api/sprints` | POST | 创建冲刺 |
| `/api/sprints/{id}/start`、`/close` | POST | 生命周期 |
| `/api/sprints/{id}/items` | POST/DELETE | 范围增删 |
| `/api/sprints/{id}/burndown` | GET | 燃尽 |
| `/api/products` | POST | 创建产品 |
| `/api/versions` | POST | 创建版本 |
| `/api/versions/{id}/items` | POST | 挂工作项 |
| `/api/worklogs` | GET/POST | 工时列表/记录 |
| `/api/worklogs/summary` | GET | 汇总 |
| `/api/worklogs/{id}/reverse` | POST | 冲正 |
| `/api/board/move` | POST | 看板移动 |

写端点全部走 BFF 签名；读端点直连（与现有 `/api/*` 一致）。

**以上 15 个端点全部已实现**，另有 `POST /api/board/move` 与 `GET /api/subjects/resolve`
（后者用于收件箱解析 `user:` 键）。

## 6. 分期与验收

| 期 | 内容 | 验收 |
|---|---|---|
| **P1** | 工作项详情（评论 + 事件 + 关联） | 能在详情页加评论、看到事件历史；刷新后仍在 |
| **P2** | 工时（记录 + 列表 + 汇总 + 冲正） | 记 90 分钟 → 列表可见 → 冲 30 → 汇总变 60；PPM 侧能收到 E7 |
| **P3** | 冲刺（创建/加项/开始/结束 + 燃尽） | 建冲刺 → 加 2 个工作项 → 开始 → 燃尽图有数据 |
| **P4** | 版本与产品（创建版本、挂项、创建产品） | 新建版本 → 挂 2 项 → 提交发布走通 |
| **P5** | 看板拖拽（通用体验三项判断为不做，见 §0） | 拖动卡片后状态真的变了 |

每期做完都要：`go vet` + `go test` + `pnpm typecheck` + `pnpm build`，
并用真栈（Keycloak + server + web）跑一次，不只看测试绿。
